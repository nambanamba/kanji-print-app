# 📝 中学受験 社会 漢字テスト＆練習プリント（印刷 & 〇✕記録アプリ）

四谷大塚「予習シリーズ」5年下・社会に準拠した、**中学受験社会の頻出漢字・記述指定重要語に特化した専用プリント作成・学習記録アプリ**です。姉妹アプリ [kosukequiz-battle](https://github.com/nambanamba/kosukequiz-battle)（対戦型一問一答クイズ）から、漢字プリント機能だけを独立させたものです。

---

## 🌟 特長

1. **入試で漢字指定・記述されやすい重要語だけを厳選**
   - `quiz_csv`（社会・通常回のクイズデータ作成チーム）が、対戦クイズの作成と合わせて回ごとに専用の漢字問題（読み仮名＋ヒント→正しい漢字）を作成しています。平易すぎる語や、答えが定まらない語は含みません。
2. **お手本も練習マスも横長。長い語も1行で大きく書ける**
   - 語は横書きなので、お手本・練習マスとも**横長**にしています。お手本はA4の全幅を使って1行で大きく表示。練習は**横に2マスずつ3段（① なぞり ＋ ②〜⑥ 練習の計6マス、各85mm×18mm）**。字数に応じて文字の大きさを自動で調整するため、「関東内陸工業地域」のような8字の語でも折り返さず1行に収まります。
3. **テスト用・練習用でA4プリントを分けて印刷**
   - ①テストプリント（読み仮名を見て正しい漢字を書く穴埋め）、②練習プリント（お手本＋なぞり書き＋4回練習マス）を、それぞれ別のシートとして印刷できます。①②は同じ問題セットを使うので、テストと練習で語がずれることはありません（単元・出題数を変えると次の印刷から新しいセットになります。手動で作り直す「🔄 出題し直す」もあります）。
4. **いらない語は自分で外せる**
   - 「進捗一覧」で語ごとに **🚫 出さない** を押すと、その語は出題にも印刷にも出なくなります（いつでも「↩︎ 戻す」で復帰）。設定は **単元＋語** で覚えるので、`福岡県` を第1回だけ外して復習編3では残す、といった使い分けができ、**データが更新されて `id` が変わっても設定は失われません**。記録の書き出し／読みこみにも含まれるので、別の端末にも引きつげます。
   - 選んだ語は **🐙 GitHubに報告して消してもらう** から、内容を入れたIssue作成画面をそのまま開けます（kosukequiz-battle の「文章を直す → GitHubに報告する」と同じやり方で、トークンは使いません）。Issueには**どの元データJSONを直せばよいか**がファイル別の表で入るので、そのままデータ削除の作業指示になります。

5. **同じ語が2回出ない**
   - 復習編は地域別の復習単元なので、`上越新幹線`（復習編2・6・7）のように同じ語が複数の単元に入っていることがあります。単元を複数選んでも**同じ語は1回だけ出題**され、進捗バー・進捗一覧・CSVの数え方も語の単位で揃います。単元を1つだけ選んだときはその単元の語がすべて出るので、単元ごとの完全性は保たれます。

6. **印刷しなくても、今日の漢字を画面で確認できる**
   - 「① 印刷・問題設定」の **👀 今日の漢字を見る（プレビュー）** で、今日の出題を漢字・読み・ヒント・今の〇✕つきで一覧できます。「漢字をかくす」を押すと答えを伏せられるので、画面のまま口頭テストにも使えます。
7. **〇✕はいつでも自由に切りかえ可能 & 未実施最優先出題**
   - 採点タブ・進捗一覧のどちらからでも〇・✕をタップした瞬間に記録され、何度でも自由に押しなおせます（二重にカウントされません）。
   - 次回の出題は「①未実施（一度も解いていない語）→②苦手（間違い＞正解）→③やや苦手（間違いはあるが正解の方が多い）→④クリア済み」の順で、各グループの中はデータの並び順（教科書の掲載順）のまま出題します（日付ソート・ランダム要素なし）。
8. **kosukequiz-battleと進捗を共有**
   - GitHub Pagesの同一オリジン（`nambanamba.github.io`）内ではlocalStorageが自動的に共有されるため、進捗記録（`kq_kanji_stats_v1`）はkosukequiz-battle側と同じ形式・同じキー名で保存しています。
   - **バージョンアップしても記録は消えません。** 旧バージョンの保存キーに記録が残っていれば初回起動時に自動で引き継ぎ、データ側で単語のidが振り直された場合も語をたよりに記録を付け替えます。
   - **別の端末・ブラウザへは「進捗一覧」タブから記録を持ち出せます。** ファイル（`kanji-stats_日付.json`）での書き出し・読みこみに加え、ファイルの受けわたしがしにくいiPadなどのために文字をコピー＆貼りつけする方法も用意しています。読みこみは置きかえではなく**マージ**で、同じ語に両方記録があるときは最後に答えた日が新しい方を残します。書き出しデータには語（`word`）も含めているため、id が振り直された後のデータにも取りこめます。
9. **スタンドアロン動作**
   - 外部サーバー不要。`index.html` をブラウザで開くだけで使えます。

## 🚀 使い方

1. `index.html` をブラウザで開きます。
2. **単元を選択**：単元ボタンをタップ（複数選択・すべて選ぶ／クリアが可能）。
3. **今日の出題語数を選択**（5語・10語・15語・20語・未クリア全問、または自由入力）。
4. **「🖨️ ① テストプリントを印刷」「🖨️ ② 練習プリントを印刷」** をタップしてA4で印刷（またはPDF保存）。同じ問題セットで両方印刷されます。
5. 紙で解いたら「② できた／できなかった」タブを開き、各語の〇・✕をタップ（その場で記録されます）。
6. 「③ 進捗一覧」で単元ごとのクリア状況を確認できます。

## 💾 記録の持ち出し・取りこみ

「進捗一覧」タブの **記録の持ち出し・取りこみ** から操作します。

| やりたいこと | 操作 |
|---|---|
| 別の端末へ移す | 📤 記録を書き出す → 移す先で 📥 ファイルから読みこむ |
| iPadなど、ファイルを渡しにくい端末 | 📋 文字でコピー → 移す先で 📝 文字を貼りつけて読みこむ |
| できた／できなかったを一覧で見たい・人に渡したい | 📊 CSVで書き出す（Excelなどで開けます） |

CSVは「全問」と「記録がある分だけ」の2種類です。列は `No, 単元, 漢字, 読み, ヒント, 出題, 結果, 正解数, まちがい数, 最後に答えた日` で、`結果` は できた／できなかった／やりなおし中／未実施、`出題` は する／出さない。Excelで文字化けしないようBOMを付けています。**CSVは書き出し専用**で、読みこみ（復元）にはJSONの方を使ってください。

- 書き出しファイルは `kanji-stats_YYYYMMDD_HHMM.json`。**ファイル名は半角のみ**にしています（日本語名だとブラウザが `download` 属性を無視し、拡張子なしの `download` で保存されることがあるため）
- 読みこみは**マージ**です。既存の記録は消えず、同じ語に両方記録がある場合は `lastAnswered` が新しい方を残します
- 書き出しデータは `{ app, type, version, exportedAt, count, stats, words }`。`words`（id→語）を持たせているので、**id が振り直された後のデータにも語で突き合わせて取りこめます**
- 別アプリのデータや壊れた内容は読みこまず、既存の記録も変更しません

## ⚠️ 開発時の注意：進捗記録の保存キーは改名しないこと

進捗記録は `localStorage` の **`kq_kanji_stats_v1`** に保存しています。過去、バージョンアップのたびにこのキー名を変えてしまい（`kanji_app_settings_mastery_v1` → `kanji_app_mastery_status_v1` → `kanji_app_mastery_simple_v1` → `kanji_app_mastery_v2` → `kq_kanji_stats_v1`）、そのたびに旧キーの記録が読まれなくなって「バージョンアップすると記録が消える」状態になっていました。

- **キー名は今後変えないでください。** 保存形式を変える必要が出た場合も、キー名は据え置いて `index.html` の `migrateLegacyMastery()` に変換処理を足してください
- キー名は kosukequiz-battle 側と共有しているため、そちらと合わせて変更しない限り改名は進捗の分断を招きます
- 「出さない」の設定は `kanji_app_excluded_v1` に `単元キー\u0000語` の形で保存します。**このキー名も改名しないこと。** `id` ではなく単元と語で持っているので、データ更新で `id` が変わっても設定は生き残ります
- **単語の `id` は振り直さないでください**（`kanji-data.js` へのデータ追加は末尾への追記のみ）。記録は `id` をキーに保存しているためです
- ⚠️ **元データJSONに `id` が無く、配列の位置から採番していることに注意。** 語を途中に足して再取り込みすると、それ以降の `id` がすべて1つずつずれ、**記録が別の語のものに入れかわります**（例：`kaki5_11` の〇が、挿入後は隣の語の〇になる）。これを防ぐため、`rescueOrphanedRecords()` が起動時に `kq_kanji_stats_words_v1`（id→語の控え）と現在の語を突き合わせ、**ずれていたら語をたよりに正しい `id` へ記録を移します**。ただし控えが無い環境（このしくみより前につけた記録、姉妹アプリ由来のid）では復元できないので、**元データ側に安定した `id` を持たせるのが本筋**です
- 語を途中に挿入する必要が出た場合は、`id` は振り直さず**末尾に新しい番号で足す**か、元データJSONに `id` を持たせて位置に依存しない採番に切り替えてください

## 🗂 元データと、消すときの影響範囲

quiz_csv 側（Googleドライブ）には、回ごとに**2種類**のJSONがあります。**漢字ファイルはクイズ本体とは別ファイル**です。

```
第1回_旧石器縄文弥生.json （クイズ本体・約46KB）  ← 対戦クイズの問題。漢字を消しても影響しない
        │ ここから漢字として出す価値のある語だけを抜き出したもの
        ▼
第1回_漢字.json （約16KB）
        ├──→ kanji-print-app の kanji-data.js（このアプリ）
        └──→ kosukequiz-battle の data.js の KANJI_DATA（漢字画面）
```

| | クイズ本体 | 漢字専用 |
|---|---|---|
| 通常回（`quiz_csv`） | `第N回_単元名.json` | `第N回_漢字.json` |
| 夏期講習（`quiz_csv_夏期講習`） | `復習編N_地方名.json` | `夏期講習_復習編N_漢字.json` |

漢字ファイルから語を消すと、**このアプリと kosukequiz-battle の漢字画面の両方から消えます**。対戦クイズの問題は減りません。

## 📁 ファイル構成

- `index.html` - アプリ本体（UI・印刷スタイル・採点・苦手管理ロジック）

## 🔄 データの更新方法

新しい回の漢字データは、`quiz_csv`（社会・通常回）が対戦クイズ本体の作成と合わせて`第{回}回_漢字.json`を作成し、kosukequiz-battle担当セッションがそれを`kanji-data.js`の`KANJI_DATA`（および`KANJI_UNITS`）に反映します。1問あたりのスキーマは以下の通りです（kosukequiz-battle側の`data.js`内`KANJI_DATA`と共通）。

```js
{ id, unit, unitKey, word, kana, mean, kai, priority, level }
```

- `id`：`k{回}_{連番2桁}`（例：`k1_01`）。対戦クイズ本体のidとは別体系
- `word`：正しい漢字（印刷のお手本・なぞり書きにそのまま使われる）
- `kana` / `mean`：読み仮名とヒント（対戦クイズ側`KANJI_DATA`の`q`フィールド「【漢字】かな\nヒント」を分割したもの）
